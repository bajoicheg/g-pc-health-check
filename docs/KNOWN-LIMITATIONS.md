# G PC Health — known limitations before managed Windows 11 acceptance

1. До проверки на реальной корпоративной Windows 11 нельзя считать подтверждёнными UAC под отдельной доменной admin-учёткой, named-pipe IPC, GUI/DPI/RDP и работу переносимой EXE во всех корпоративных GPO/EDR-сценариях. Hosted Windows Server CI не заменяет эту проверку.
2. WMI/CIM и SecurityCenter2 могут вести себя по-разному на корпоративных образах; отсутствие данных не должно интерпретироваться как исправность.
3. Основная диагностика агрегирует Critical/Error по System/Application; отдельный разбор сбоя показывает события выбранного интервала. Корреляцию повторяющихся Provider/Event ID с жалобой «ПК тормозит» нужно проверять на реальных инцидентах.
4. DISM/SFC остаются ручным выбором инженера и не должны становиться автоматической «оптимизацией».
5. Authenticode code signing пока не включён; проверяйте SHA-256 и build provenance и используйте утверждённый канал распространения. С 0.5.2 приложение разрешает административные действия из любого допустимого расположения и с любым именем EXE; корпоративные политики запуска и права Windows продолжают действовать.
6. Пороговые значения Health Score являются эвристикой Service Desk и требуют калибровки на реальных инцидентах.
7. Установка в Program Files не требуется. Переносимая `G-PC-Health.exe` сохраняет UAC, фиксированный allow-list и session/nonce-bound worker; CleanTemp требует проверенного контекста того же пользователя без elevation. Не перемещайте и не переименовывайте EXE во время её работы.
8. 0.17.0 остаётся кандидатом: повторный managed-Windows пилот, независимое ревью и явное разрешение владельца на интеграцию ещё нужны. Ребрендинг исходников сам по себе не создаёт новый проверенный EXE. См. [актуальное состояние и следующие шаги](REBRANDING.md).
