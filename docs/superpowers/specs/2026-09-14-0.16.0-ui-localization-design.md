# 0.16.0 — UI, localization and analysis workflow design

## Scope

This sub-spec covers only operator-facing presentation and navigation changes for 0.16.0:

- human-readable MB file/folder sizes;
- safe auto-collection when an Analysis window opens from the main menu;
- RU/EN localization with persistent in-app switching;
- `© 2026 V. Vasilev` attribution in About;
- corrected shield/background rendering;
- language/branding regression coverage.

It does not define remediation actions or green/red batch semantics; those are specified separately.

## Size presentation

Raw byte counts remain the evidence source of truth. Human-facing views must not show file/folder sizes primarily as raw bytes.

Introduce one shared formatting rule:

- file/folder byte counts displayed in tables, detail panes, HTML and clipboard summaries are shown as **MB** with one decimal by default;
- use invariant calculation `bytes / 1024d / 1024d`;
- locale-aware numeric separators follow the selected UI culture;
- zero is `0.0 MB` (or the culture-equivalent formatted number);
- unknown/unavailable size remains `—` / `N/A`, not `0 MB`;
- sorting must use raw numeric bytes/MB values, not lexicographic display strings;
- machine-readable JSON keeps raw byte fields unchanged. A supplemental display field may be added only if it is clearly presentation-only and does not replace the raw value.

This applies at minimum to Temp preview largest files, folder/storage analysis, file-use evidence where a file size is shown, and generated human-readable storage/Temp reports. Existing whole-disk free-space metrics expressed in GB are not changed merely for consistency; the requirement is specifically file/folder sizes that currently expose bytes.

## Analysis auto-collection

The user expectation is: an Analysis window opened from the main menu should perform the same safe action as pressing its existing **Собрать / Collect** button immediately after the form is shown, when the request is already fully defined.

Use the form `Shown` lifecycle, not constructor-time async work, so controls and synchronization context exist before collection begins.

### Auto-start when no additional target or consent is required

Auto-start the existing default collection for:

- Temp preview;
- startup review;
- incident/event review with its default window/options;
- current-process review;
- endpoint review;
- storage details and any folder-storage view whose default target is already fully defined by the form;
- Performance Session using the existing default duration/interval;
- Diagnostic Bundle using the existing default Quick mode and category set;
- other Analysis menu items whose existing `Collect` operation is read-only and needs no additional user input.

Auto-start must call the same operation path as the Collect button; do not duplicate collector logic or create a second status/error path.

### Do not auto-start when the request is not yet defined

Remain idle and focus the required input for:

- Resource Probe until host/port and explicit outbound consent are present;
- File Use until a local file target has been chosen;
- Process Observation until a process/PID target is selected;
- any future tool that requires an explicit target, privacy opt-in or network consent not already satisfied by opening the window.

Opening a form must never be treated as implicit consent for an outbound request or a destructive operation.

### Reopen and concurrency behavior

Existing static/provider busy gates remain authoritative. If a tool cannot start because the same collector is already active, the newly opened form shows the existing busy state rather than launching a second collector. Closing during collection uses the current cancellation semantics.

## RU/EN localization architecture

Use one central localization service backed by embedded .NET resources, rather than duplicating dictionaries inside forms.

Recommended resource shape:

- neutral/default resource contains Russian strings;
- `en` resource contains English equivalents;
- code addresses stable resource keys, never branches on translated text;
- action IDs, JSON keys, schema values and internal state enums stay language-neutral.

The localization service owns:

- selected `CultureInfo`;
- `T(key)` / formatted lookup helpers;
- fallback to Russian for missing/invalid persisted settings;
- persisted language preference;
- a culture-change notification used by the main window/menu.

Persist only a small language code (`ru` or `en`) in a user-local settings file under the application's existing/local application-data convention. A missing, malformed or unreadable settings file must not stop diagnostics; default to Russian and continue.

Do not infer language from Windows every launch after the user has explicitly chosen one.

## Runtime switching UX

The main menu contains visible language affordances:

- `🇷🇺 RU` with tooltip **Русский** / **Russian**;
- `🇬🇧 EN` with tooltip **English** / **Английский**.

The selected language is visibly checked/marked. Clicking a language item:

1. updates the persisted preference;
2. updates the current UI culture;
3. refreshes main-window/menu/operator text without restarting the program;
4. causes subsequently opened modal Analysis dialogs to use the selected language.

Current Analysis dialogs are modal; therefore the main language switch is not available while one is open. No hidden requirement is added to live-retranslate a modal dialog that blocks the main menu. If a future modeless window exists, it may either subscribe to culture changes or document that it refreshes when reopened.

## Localization coverage

0.16.0 should not be a partial “English menu over Russian internals” release. Localize operator-facing product text, including:

- main dashboard labels, tabs, buttons and status;
- menu titles and Windows-tools entries;
- all Analysis form labels/buttons/statuses/tooltips;
- confirmation/warning/error dialogs produced by application code;
- remediation action titles, risk labels, availability text and verification instructions;
- generated human-readable HTML headings and clipboard summaries;
- About dialog.

Do not translate raw evidence emitted by Windows/providers (event message text, product names, file paths, service names, command stdout/stderr). Reports may therefore contain localized product framing plus raw Windows evidence.

## About / attribution

Add **О программе… / About…** under a conventional **Справка / Help** menu.

The dialog contains at minimum:

- `G PC Health Check`;
- application version read from the executing assembly/file metadata, not hard-coded independently;
- `© 2026 V. Vasilev`;
- a concise statement that the tool is intended for Windows 11 Service Desk diagnostics and controlled actions;
- no email, account name, private company data or telemetry link unless separately approved.

Use exactly the typographically conventional ordering `© 2026 V. Vasilev`.

## Shield/background correction

The main header must not show a visibly different rectangular background around the shield.

Implementation requirements:

- the picture/control background matches the surrounding card;
- if the current source PNG contains an opaque uniform background, generate/use a transparent-background derivative while preserving shield pixels;
- do not crop or stretch the shield disproportionately;
- rendering remains clean at DPI 100/150/200;
- build-time brand provenance checks are updated deliberately if the generated asset hash changes; do not weaken/remove those checks merely to accept a changed asset.

A focused image/asset self-test should at least verify that corner pixels in the rendered/source asset are transparent or match the intended card background and that expected dimensions/content are non-empty. Real visual acceptance still happens on Windows 11.

## Interaction with resize-paint fix

The 0.15.1 post-release resize fix (`#86`) remains part of the 0.16.0 baseline. Localization, menu rebuilding or shield changes must not reintroduce the stale-card-border trail. The existing resize-redraw self-test remains enabled.

## Test-first requirements

Focused RED tests must cover at minimum:

- byte-to-MB formatting, culture separators and unknown values;
- table sorting remaining numeric after MB presentation;
- safe auto-start fires exactly once from `Shown` for forms that require no target;
- target/consent-required forms remain idle on open;
- RU default and EN resource lookup;
- persistence and invalid-settings fallback;
- language switching does not change stable IDs/schema values;
- main menu has idempotent RU/EN controls and About entry;
- About uses running version and exact `© 2026 V. Vasilev` text;
- shield background regression contract;
- all prior UI/self-tests continue to pass.

Hosted CI can validate control/resource contracts, not the complete appearance. Managed Windows pilot must verify both languages at DPI 100/150/200, main-window resize, shield blending and first-open auto-collection.
