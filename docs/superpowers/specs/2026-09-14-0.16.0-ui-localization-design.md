# 0.16.0 — UI, localization and analysis workflow design

## Scope

This sub-spec covers only operator-facing presentation and navigation changes for 0.16.0:

- human-readable MB file/folder sizes;
- safe auto-collection when an Analysis window opens from the main menu;
- RU/EN localization with persistent in-app switching;
- `© 2026 V. Vasilev` attribution in About;
- corrected shield/background rendering;
- language/branding regression coverage.

It does not define remediation actions or green/red batch semantics; those are specified separately.

## Size presentation

Raw byte counts remain the evidence source of truth. Human-facing views must not show file/folder sizes primarily as raw bytes.

Use one shared formatting rule:

- file/folder byte counts displayed in tables, detail panes, HTML and clipboard summaries are shown as **MB** with one decimal;
- calculation is `bytes / 1024d / 1024d`;
- locale-aware numeric separators follow the selected UI culture;
- zero is `0.0 MB` in English and the culture-equivalent formatted value in Russian;
- unknown/unavailable size remains `—` / localized `N/A`, never `0 MB`;
- sorting uses raw numeric bytes/MB values, never lexicographic display strings;
- machine-readable JSON keeps raw byte fields unchanged. A supplemental display field may be added only as explicitly presentation-only metadata and must not replace raw bytes.

Apply this to the current Temp preview largest-file table/report, Storage folder analysis (folders and largest files), and any File Use/current evidence surface that displays a file size. Existing whole-disk free-space metrics expressed in GB remain in GB; the requirement is specifically file/folder sizes that currently expose raw bytes.

## Analysis auto-collection

The user expectation is: an Analysis window opened from the main menu performs the same safe action as pressing its existing **Собрать / Collect** button immediately after the form is shown, when the request is already fully defined.

Use the form `Shown` lifecycle, not constructor-time async work, so controls and synchronization context exist before collection begins. Auto-start must call the same operation path as the Collect button; do not duplicate collector logic or create a second status/error path.

### Auto-start current fully-defined Analysis tools

Auto-start exactly once per newly opened form for:

- Temp preview;
- startup review;
- incident/event review using its existing default time window/options;
- current-process review;
- endpoint review;
- Storage **folder analysis** using its existing default root (current user profile) and default limits;
- Storage **disk details**;
- Performance Session using its existing default duration/interval;
- Diagnostic Bundle using the existing default **Quick** mode/category set.

Opening these forms is sufficient because their default read-only request is already defined by existing UI state.

### Remain idle when the request is not defined

Do not auto-start:

- Resource Probe — host/port and explicit outbound consent are required;
- File Use — a local file target is required;
- Process Observation — a process/PID target is required.

Focus the first required input/selector so the engineer can start quickly. Opening a form is never implicit consent for an outbound request or destructive operation.

### Reopen and concurrency behavior

Existing static/provider busy gates remain authoritative. If a tool cannot start because the same collector is already active, the newly opened form shows the existing busy state rather than launching a second collector. Closing during collection uses the current cancellation semantics.

## RU/EN localization architecture

Use one central localization service backed by embedded .NET resources. Do not duplicate ad-hoc dictionaries inside forms.

Required resource shape:

- neutral/default embedded resource contains Russian strings;
- `en` resource contains English equivalents;
- code addresses stable resource keys and never branches on translated text;
- action IDs, JSON keys, schema values and internal enums remain language-neutral.

The localization service owns:

- selected `CultureInfo` / `CurrentUICulture` for product text;
- `T(key)` and formatted lookup helpers;
- Russian fallback for a missing key or invalid persisted setting;
- loading/saving the language preference;
- a culture-change notification used by the main window/menu.

Persist only `{ "language": "ru" }` or `{ "language": "en" }` in `%LocalAppData%\G-PC-Health-Check\settings.json`. Create the directory/file only when a preference must be saved. A missing, malformed or unreadable settings file must not stop diagnostics; default to Russian and continue.

After the user explicitly chooses a language, do not replace that choice with Windows locale detection on later launches.

## Runtime switching UX

The main menu contains visible language affordances:

- `🇷🇺 RU` with tooltip **Русский** in RU UI and **Russian** in EN UI;
- `🇬🇧 EN` with tooltip **Английский** in RU UI and **English** in EN UI.

The selected language is visibly checked/marked. Clicking a language item:

1. saves the preference;
2. updates current culture/UI culture;
3. retranslates main-window labels/tabs/buttons/status and all top-level/drop-down menu text without restarting;
4. causes subsequently opened modal Analysis dialogs to use the selected language.

Current Analysis dialogs are modal, so the main language controls cannot be operated while one blocks the main window. 0.16.0 therefore does not require live retranslation of an already-open modal dialog; close/reopen uses the new language.

## Localization coverage

0.16.0 is not a partial “English menu over Russian internals” release. Localize operator-facing product text, including:

- main dashboard labels, tabs, buttons and product statuses;
- menu titles and Windows-tools entries;
- all Analysis form labels/buttons/statuses/tooltips;
- confirmation/warning/error framing produced by application code;
- remediation action titles, risk labels, availability text and verification instructions;
- generated human-readable HTML headings/descriptions and clipboard summaries;
- About dialog.

Do not machine-translate raw evidence emitted by Windows/providers (event messages, product names, file paths, service names, command stdout/stderr). A report can therefore contain localized product framing plus raw Windows evidence.

## About / attribution

Add **О программе… / About…** under **Справка / Help**.

The dialog contains:

- `G PC Health Check`;
- application version read from the executing assembly/file metadata, not independently hard-coded;
- exact text `© 2026 V. Vasilev`;
- localized concise description: Windows 11 Service Desk diagnostics and controlled actions;
- no email, account name, private company data or telemetry link unless separately approved.

## Shield/background correction

The main header must not show a visibly different rectangular background around the shield.

Implementation requirements:

- picture/control background matches the surrounding white card;
- inspect the existing `g-shield.png`; if corner/background pixels are opaque, generate/use a transparent-background derivative that changes only the uniform background outside the shield, preserving shield artwork;
- do not crop or stretch the shield disproportionately;
- rendering remains clean at DPI 100/150/200;
- build-time brand provenance checks are updated deliberately if a generated/source asset hash changes; never weaken/remove the existing verification just to accept new bytes.

A focused asset self-test verifies non-empty expected dimensions and that corner/background pixels are transparent or exactly match the intended card background. Real visual acceptance still happens on managed Windows 11.

## Interaction with resize-paint fix

The 0.15.1 post-release resize fix (`#86`) remains part of the 0.16.0 baseline. Localization, menu rebuilding or shield changes must not reintroduce stale rounded-card border trails. Keep the resize-redraw self-test enabled.

## Test-first requirements

Focused RED tests cover at minimum:

- byte-to-MB formatting, RU/EN separators and unknown values;
- numeric sorting after MB presentation;
- every listed auto-start form invokes its existing collect path exactly once from `Shown`;
- Resource Probe/File Use/Process Observation remain idle on open and focus required input;
- RU default and EN resource lookup;
- exact `%LocalAppData%` preference persistence and malformed-settings fallback;
- language switching does not change stable IDs/schema values;
- main menu has idempotent RU/EN controls and Help/About entry;
- main-window/menu visible text retranslates without process restart;
- About uses running version and exact `© 2026 V. Vasilev` text;
- shield background regression contract;
- all prior UI/self-tests continue to pass.

Hosted CI validates control/resource contracts, not complete appearance. Managed Windows pilot verifies both languages at DPI 100/150/200, main-window resize, shield blending and first-open auto-collection.
