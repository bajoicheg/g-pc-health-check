# 0.17.0 Security Posture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship G PC Health Check 0.17.0 with a separate, truthful Endpoint Security Posture score and coverage, detailed Security tab, firmware/storage/local-administrator controls, centrally managed ADMX allow-list policy, and a conservative blue `Усилить защиту / Harden security` batch while preserving the existing technical Health Score and 0.16.0 remediation boundaries.

**Architecture:** Keep one portable Windows x64 EXE. Add a security-specific typed snapshot/evaluator pipeline beside the existing technical diagnostics, then layer read-only Windows/provider collectors, vendor-specific firmware adapters, the local-Administrators machine policy, UI/reporting, and a separate fixed security-hardening registry that reuses the authenticated worker transport without merging security actions into the red Service Desk batch. Missing or ambiguous evidence remains `Unknown`; the evaluator alone owns score, coverage and critical-band overrides.

**Tech Stack:** C# / .NET 8.0.425, WinForms, `System.Management`, Windows Registry, Win32/COM interop, Windows Update Agent COM, Windows Security Center interfaces, BitLocker WMI, NetAPI32 local-group enumeration, embedded `.resx`, XML ADMX/ADML, existing named-pipe/UAC worker, existing PowerShell build/dev scripts, GitHub Actions Windows CI.

## Global Constraints

- Keep one portable Windows x64 EXE; arbitrary valid EXE path/name remains supported.
- Preserve existing technical `Assessment.Score`, `Assessment.Status` and technical coverage semantics. Security never changes the technical Health Score.
- Endpoint runtime requires no adjacent JSON/INI/XML policy file.
- Local-administrator policy is read-only at `HKLM\SOFTWARE\Policies\GPCHealthCheck\AllowedLocalAdministrators` as `REG_MULTI_SZ`; no per-user settings fallback.
- ADMX/ADML are deployment/admin artifacts, not runtime dependencies.
- Local-admin wildcard language is exactly `*` = zero or more characters and `?` = exactly one character; every other character is literal; whole-string, case-insensitive matching; no regex/environment expansion.
- Administrators group is discovered by well-known SID `S-1-5-32-544`, never by localized group name.
- Security posture v1 final configured weights sum exactly to 100: AV active 9, AV platform 2, AV definitions 8, AV RTP 8, AV tamper 3, firewall 11, OS updates 10, BitLocker OS 8, BitLocker data 5, Secure Boot 6, BIOS admin password 5, boot restrictions 4, UAC 4, TPM 4, VBS/HVCI 5, local Administrators 8.
- `Unknown` lowers security coverage and never becomes `Pass`; coverage below 80% forces `AssessmentIncomplete` presentation.
- Critical caps: confirmed AV disabled -> `Low`; effective firewall absent/disabled -> `Low`; OS volume unprotected -> `Low`; unauthorized local administrator -> `Low`; severely stale OS update, UAC disabled, BIOS admin password missing, external boot violation, or unprotected fixed data volume -> no better than `NeedsAttention`.
- Firmware/boot/password/BitLocker/local-admin controls are assessment/manual-remediation only in 0.17.0.
- Never read, request, store, hash or export BIOS passwords, BitLocker recovery material, AV/EDR secrets, credentials or browser secrets.
- Do not install Dell/HP/Lenovo management tooling. Existing trusted local OEM interfaces may be used; otherwise return `Unknown`.
- Blue hardening never sets firmware passwords, changes boot order, enables BitLocker, modifies local Administrators, changes UAC/TPM/VBS, installs Windows updates, disables security controls, bypasses policy/tamper protection, or changes WSUS/update source.
- Kaspersky RTP is read-only in 0.17.0; the only Kaspersky automatic candidate is a fixed supported database/definitions update when local policy permits it.
- Red `Do everything` keeps its exact 0.16.0 intent and must not absorb blue security-hardening actions.
- No generic PowerShell/CMD/executable/service/registry interface is exposed to UI or worker. Fixed code-owned commands are permitted only for a named security action with no user-supplied executable/arguments.
- Hosted CI uses synthetic/fake native boundaries and does not deliberately weaken real security controls. Real Windows 11 provider/OEM behavior requires managed pilot acceptance.
- Every implementation task follows RED -> minimal GREEN -> regression GREEN -> commit.
- Use `pwsh -NoProfile -File tools/dev/Invoke-DevCheck.ps1 -Profile Quick` for iteration when a prepared Windows checkout is available; use `-Profile Full` before final candidate; connector-only execution uses exact-head Windows CI.
- Do not bump application version to 0.17.0 until all functional tasks are GREEN and release docs are being finalized.

- [ ] **Step 1: Add RED evaluator self-test for exact catalog and score math.**

```csharp
Require(SecurityControlCatalog.All.Sum(x => x.Weight) == 100, "Security weights must equal 100.");

Require(assessment.Score == 100, "All-pass score must be 100.");
Require(assessment.CoveragePercent == 100, "All-pass coverage must be 100.");
```

- [ ] **Step 2: Add RED critical-cap tests using explicit band severity.**

```csharp

Require(EvaluateWithFail("SEC-BITLOCKER-OS").DisplayBand == SecurityBand.Low, "OS encryption fail cap missing.");

Require(IsNoBetterThan(EvaluateWithFail("SEC-BIOS-ADMIN-PASSWORD").DisplayBand, SecurityBand.NeedsAttention), "BIOS password cap missing.");
```

```csharp
var known = controls.Where(IsKnown).ToArray();
var applicable = controls.Where(x => x.Status != SecurityControlStatus.NotApplicable).ToArray();
var coverage = applicable.Length == 0 ? 0 : (int)Math.Round(known.Sum(x => x.Weight) * 100d / applicable.Sum(x => x.Weight));
var knownWeight = known.Sum(x => x.Weight);
var score = knownWeight == 0 ? null : (int?)Math.Round(known.Sum(x => x.Weight * x.EarnedFraction) * 100d / knownWeight);
```
