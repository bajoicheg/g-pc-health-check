# 0.17.0 — Endpoint Security Posture and safe hardening

## Purpose

0.17.0 adds a separate, evidence-based endpoint-security posture layer to G PC Health Check while preserving the existing technical Health Score and the 0.16.0 Service Desk remediation boundaries. The application remains one portable Windows 11 x64 EXE with no installer and no adjacent runtime policy/configuration file.

A workstation can be technically healthy but insecure, or technically unhealthy while its security controls are configured correctly. For that reason the technical score/coverage and the new Security score/coverage are intentionally independent.

## New Security posture

The main window adds a seventh **ИБ / SECURITY** metric card and a dedicated **ИБ / Security** tab. The Security card shows a separate score, qualitative band and telemetry coverage. The tab keeps stable control IDs, raw evidence and operator guidance separate from localized RU/EN presentation.

Endpoint Security Posture v1 contains exactly 100 weighted points:

| Control | Weight |
|---|---:|
| `SEC-AV-ACTIVE` | 9 |
| `SEC-AV-PLATFORM` | 2 |
| `SEC-AV-DEFINITIONS` | 8 |
| `SEC-AV-RTP` | 8 |
| `SEC-AV-TAMPER` | 3 |
| `SEC-FIREWALL` | 11 |
| `SEC-OS-UPDATES` | 10 |
| `SEC-BITLOCKER-OS` | 8 |
| `SEC-BITLOCKER-DATA` | 5 |
| `SEC-SECUREBOOT` | 6 |
| `SEC-BIOS-ADMIN-PASSWORD` | 5 |
| `SEC-BOOT-RESTRICTIONS` | 4 |
| `SEC-UAC` | 4 |
| `SEC-TPM` | 4 |
| `SEC-VBS-HVCI` | 5 |
| `SEC-LOCAL-ADMINS` | 8 |

`Pass`, `Warn` and `Fail` are known evidence. `Unknown` is not scored as failure and is never converted to healthy; instead it lowers Security coverage. `NotApplicable` is removed only when irrelevance is positively established. Coverage below 80% forces **Assessment incomplete / Оценка неполная**, even when the numeric score from known controls is high.

Critical confirmed failures can cap the displayed band independently of arithmetic. In particular disabled primary AV, absent/disabled effective firewall, unprotected OS volume and an unauthorized direct local administrator cap the band at `Low`. Severe OS-update staleness, disabled UAC, missing BIOS admin password, external-boot violation and unprotected applicable data volumes cap it at no better than `NeedsAttention`.

## Security evidence sources

0.17.0 adds focused, read-only collectors for:

- Windows Security Center provider state;
- Microsoft Defender local state;
- Kaspersky Endpoint Security read-only KESCLI/OPSWAT state where the installed local interface is available;
- effective Windows/third-party firewall ownership and Windows Firewall profiles;
- Windows Update Agent history/search against the machine's already configured update source, including enterprise WSUS;
- BitLocker OS and applicable fixed-data volumes without collecting recovery material;
- Secure Boot/UEFI, UAC, TPM and VBS/HVCI runtime state;
- BIOS/UEFI password and boot restrictions through already-present trusted Lenovo/Dell/HP provider interfaces;
- direct members of the local Administrators group discovered by well-known SID `S-1-5-32-544`.

Unsupported, unavailable or ambiguous provider/OEM evidence remains `Unknown`. The application never installs Lenovo, Dell or HP management tooling merely to obtain posture data.

## Local Administrators policy and ADMX

The endpoint reads the machine policy only from:

`HKLM\SOFTWARE\Policies\GPCHealthCheck\AllowedLocalAdministrators`

The Registry value must be `REG_MULTI_SZ`. ADMX/ADML deployment artifacts are supplied under `policy/` for central administration:

- `policy/GPCHealthCheck.admx`;
- `policy/en-US/GPCHealthCheck.adml`;
- `policy/ru-RU/GPCHealthCheck.adml`.

Administrative Templates path:

`Computer Configuration -> Administrative Templates -> G PC Health Check -> Security Posture -> Allowed local administrators`

The allow-list is one pattern per line. Matching is whole-string and case-insensitive:

- `*` = zero or more characters;
- `?` = exactly one character;
- every other character is literal;
- no regular expressions or environment-variable expansion.

Rules can match normalized names such as `CONTOSO\adm-*` and SID identities such as `SID:S-1-5-21-*-500`. `LOCAL\` is normalized to the current computer. An explicitly enabled policy with an empty effective list permits no direct principal. Missing, wrong-type or unreadable policy remains `Unknown`; the program does not invent a local fallback configuration.

ADMX/ADML are administrator deployment artifacts only. They are not embedded as runtime authorization data and no policy file is required beside the portable EXE.

## Blue Harden security batch

The main action area now has three deliberately separate buttons in this order:

1. blue **Усилить защиту / Harden security** (`#2386C0`);
2. green **Сделать хорошо / Make it better** (`#177A4B`);
3. red **Сделать всё / Do everything** (`#B53636`).

The red button is never the default Enter action.

The blue path uses a separate fixed registry and can automatically request only three action IDs:

1. `SecurityUpdateAvDefinitions` — Defender signatures or Kaspersky definitions/database update when the supported local provider interface and policy permit it;
2. `SecurityEnablePrimaryRtp` — Defender-only real-time protection enablement in 0.17.0;
3. `SecurityEnableWindowsFirewall` — only when Windows Defender Firewall is positively identified as the intended effective provider, no third-party firewall owns the function, and the disabled state is locally controllable rather than centrally enforced.

The blue workflow performs a fresh Security/context preflight, shows exact runnable/skipped actions and reasons, asks once for confirmation, requests at most one UAC elevation for the fixed security worker, and then performs a separate fresh Security recollection. A successful command exit alone is never reported as proof that the control is fixed.

Security worker traffic is explicitly namespaced and session/nonce bound. Security action IDs cannot enter the Service Desk worker namespace, and the original 0.16.0 red batch remains the same fixed 14-action set.

## Explicitly manual in 0.17.0

The blue path does **not** automatically:

- set/change BIOS or UEFI passwords;
- change firmware boot order or Secure Boot;
- enable/provision BitLocker or create/export/rotate recovery keys;
- change local Administrators membership;
- initialize, clear or reprovision TPM;
- enable VBS/HVCI/Memory Integrity;
- change UAC policy;
- install Windows quality/security updates or change WSUS/update source;
- reboot or log off;
- install, upgrade or uninstall AV/EDR;
- enable Kaspersky RTP or other KES protection components;
- add/change AV exclusions;
- disable, weaken or bypass AV/EDR/firewall/tamper protection/central management.

These controls remain assessment plus operator guidance only.

## Evidence and secret boundary

HTML, public JSON and clipboard output include bounded normalized Security assessment/evidence, model version, score, coverage, control states and collection warnings. The internal raw snapshot is excluded from public JSON. Raw native output from security mutation commands is also kept internal and is not JSON-serialized.

The tool must never collect/export BIOS passwords, BitLocker recovery passwords/keys, AV/EDR passwords or tokens, credentials, cookies or browser secrets.

## Existing Service Desk behavior remains unchanged

The green batch remains routine technical remediation. The red **Do everything** remains exactly these 14 code-owned actions and does not absorb blue security actions:

`CleanTemp`, `FlushDns`, `RegisterDns`, `DhcpReleaseRenew`, `WinsockReset`, `TcpIpReset`, `RestartNetworkAdapters`, `RestartSpooler`, `ClearPrintQueue`, `RestartUpdateServices`, `GpUpdate`, `TimeResync`, `Dism`, `Sfc`.

The existing Service Desk one-UAC phased worker, original-user Temp boundary, session/nonce authentication and portable path/name behavior remain intact.

## Validation boundary and managed pilot

Hosted Windows CI verifies deterministic source/published-EXE self-tests, warnings-as-errors, transitive NuGet audit, portable worker/security negative tests, FileVersion/checksum and pilot-bundle construction. It uses synthetic/fake boundaries for security mutation and does not deliberately weaken the hosted runner.

Hosted Windows Server CI cannot prove real Windows 11 provider/OEM/GPO/UAC behavior. Before production rollout, perform the managed pilot matrix documented in [`docs/releases/0.17.0-validation.md`](0.17.0-validation.md) and [`docs/E2E-TEST-PLAN.md`](../E2E-TEST-PLAN.md), including Defender-primary and Kaspersky-primary endpoints, enterprise update source, firewall ownership, BitLocker OS/data, Secure Boot/TPM/VBS, representative supported/unsupported OEM firmware, ADMX local-admin rules, RU/EN, DPI and blue hardening on an approved test workstation.

Do not intentionally weaken production security or remove legitimate administrative access just to manufacture a failure. Use disposable or specifically approved test endpoints for degraded/destructive cases.
