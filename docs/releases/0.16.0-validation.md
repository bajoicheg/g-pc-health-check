## Security and execution review boundary

0.16.0 keeps the following hard requirements:

- exact fixed 14-action red batch only; no arbitrary command, executable, service name or adapter name;
- session/nonce-bound authenticated phased worker protocol;
- one worker lifetime / one UAC for administrative batch work;
- original-user actions remain bound to the verified interactive user/session/profile;
- alternate-admin elevation does not impersonate the interactive user;
- network-disruptive actions remain late in the phase plan;
- no disabling, stopping, excluding or weakening AV/EDR/firewall/protective software;
- no forced reboot/logoff, Event Log clearing, credential/profile deletion or hidden elevation;
- missing telemetry remains unknown/partial rather than healthy by implication;
- localized operator framing does not translate stable IDs, JSON keys or raw provider evidence.

Hosted CI tests disruptive repair behavior through fixed native-operation boundaries, fakes and negative tests. It does not execute the real red 14-action batch on the shared Windows runner.

## Managed Windows pilot blocker boundary

The red **Do everything / Сделать всё** path must first be exercised only on an approved disposable/test workstation. It may interrupt VPN/RDP/network connectivity, release/renew DHCP, reset Winsock/TCP-IP, restart adapters/services, delete pending print jobs, refresh Group Policy, resynchronize time, run DISM/SFC and leave Windows requiring reboot.

Hosted-CI success is not evidence that this real disruptive sequence has passed on corporate Windows 11. The managed acceptance plan in `docs/E2E-TEST-PLAN.md` remains the required pilot gate for interactive UAC/alternate-admin identity, RDP/DPI, VPN/EDR coexistence, OEM/storage diversity and actual disruption/recovery behavior.
