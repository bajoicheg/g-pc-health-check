## Security model invariants

Endpoint Security Posture v1 retains exactly 100 configured weighted points across 16 controls. `Unknown` lowers Security coverage instead of becoming failure or healthy. Coverage below 80% forces `AssessmentIncomplete` presentation.

The separate technical Health Score/coverage model is unchanged.

The 0.16.0 Service Desk registry remains exactly 14 actions. The red `Do everything / Сделать всё` set contains no Security action. The blue hardening registry is separate and contains exactly:

- `SecurityUpdateAvDefinitions`;
- `SecurityEnablePrimaryRtp`;
- `SecurityEnableWindowsFirewall`.

Kaspersky RTP is read-only/manual in 0.17.0 and `SecurityEnableKasperskyRtp` does not exist.

## Security execution boundaries

0.17.0 keeps these hard requirements:

- separate `ServiceDesk` and `SecurityHardening` worker namespaces;
- session/nonce-bound worker messages;
- no security action accepted by the Service Desk namespace and no Service Desk action accepted by the Security namespace;
- blue execution requires fresh raw Security posture plus fresh execution-context preflight;
- a rendered/saved public scan is not an authorization credential;
- one fixed security worker and at most one UAC decision for an approved blue batch;
- post-action recollection is required before claiming improvement;
- no generic command/executable/service/registry/principal/password/token mutation API;
- no security-weakening action;
- raw native security-operation output is internal and excluded from JSON serialization.

## Local Administrators / ADMX boundary

Runtime policy source:

`HKLM\SOFTWARE\Policies\GPCHealthCheck\AllowedLocalAdministrators` (`REG_MULTI_SZ`).

Administrative Templates artifacts:

- `policy/GPCHealthCheck.admx`;
- `policy/en-US/GPCHealthCheck.adml`;
- `policy/ru-RU/GPCHealthCheck.adml`.

Pattern language is whole-string, case-insensitive `*`/`?` only. `*` is zero or more characters, `?` exactly one; all other characters are literal. SID rules are supported. Administrators discovery is anchored on `S-1-5-32-544`, not the localized group name.

The policy artifacts are deployment-only: source and published single-file self-tests prove that the EXE does not need `.admx`/`.adml` files or adjacent configuration at runtime.

## OEM / telemetry limitations

BIOS/UEFI password and boot restriction checks can return reliable results only where an already-present supported Lenovo, Dell or HP provider exposes sufficient trusted read-only telemetry. 0.17.0 does not install OEM management software. Unsupported or ambiguous firmware evidence is `Unknown`.

Likewise, provider/platform version, tamper/self-protection and other Security fields remain `Unknown` unless trustworthy local interfaces prove the state. Missing telemetry is never interpreted as healthy.

## Explicitly non-automatic controls

0.17.0 does not automatically mutate firmware passwords/boot order/Secure Boot, BitLocker/recovery material, local Administrators membership, TPM, VBS/HVCI, UAC, Windows quality/security updates/update source, Kaspersky RTP, AV exclusions or security/tamper/central-management policy. It does not install/upgrade/uninstall AV/EDR and does not force reboot/logoff.

## Managed Windows 11 pilot acceptance — required, not proven by hosted CI

Hosted Windows Server CI is not evidence of real managed Windows 11 provider/OEM/GPO/UAC behavior. Before production rollout the following matrix must be executed on approved Windows 11 test/pilot endpoints and recorded with evidence:

- Defender-primary endpoint;
- Kaspersky-primary endpoint with passive Defender;
- effective Windows Firewall and active third-party firewall ownership cases;
- enterprise-configured Windows Update/WSUS source including an update-pending case;
- BitLocker protected/unprotected OS and applicable fixed-data evidence without collecting recovery material;
- Secure Boot, TPM 2.0 and VBS/HVCI runtime cases;
- supported Lenovo/Dell/HP firmware provider examples where hardware is available;
- unsupported OEM/provider proving `Unknown` rather than false Pass/Fail;
- ADMX-delivered local Administrator rules: exact, `*`, `?`, SID, explicit empty list and missing/unreadable policy;
- unauthorized local-admin FAIL only on a disposable/approved test endpoint; do not remove legitimate production access to manufacture a test;
- standard user, administrator member with UAC, already-elevated administrator and alternate-admin UAC path;
- RU/EN operator UI;
- DPI 100%, 150%, 200% and resizing;
- blue hardening on an approved test workstation, including fresh before/after recollection and policy-blocked behavior;
- regression of the red 14-action path only on an approved disposable/test workstation because it may interrupt network/VPN/RDP and leave reboot-required state.
