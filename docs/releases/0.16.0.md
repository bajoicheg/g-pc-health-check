# 0.16.0 — bilingual Service Desk actions and one-click repair

## Purpose

0.16.0 is the first release that combines bilingual RU/EN operator UX with a centralized Service Desk remediation model and an explicit one-UAC phased repair batch. It keeps the product as one portable Windows 11 x64 EXE and preserves the existing evidence, execution-context and Temp-safety boundaries.

## What is new

- RU/EN operator UI with in-app language switching and persisted preference. Stable control/action IDs, JSON keys and raw provider evidence do not change with language.
- Human-readable file/folder sizes are shown in MB while raw JSON byte values remain unchanged.
- Safe read-only Analysis windows with fully defined default scope can auto-collect once on open; target/consent-required tools remain idle.
- About/branding cleanup, including the running version and `© 2026 V. Vasilev`.
- Centralized Service Desk action registry with stable IDs, risk/impact metadata, execution host and verification metadata.
- Select All plus two explicit batch paths:
  - **Make it better / Сделать хорошо** — only currently recommended, automated and requestable actions;
  - **Do everything / Сделать всё** — the fixed, code-owned 14-action allow-list below.

## Fixed 14-action red batch

The explicit red batch contains exactly:

1. `CleanTemp`
2. `FlushDns`
3. `RegisterDns`
4. `DhcpReleaseRenew`
5. `WinsockReset`
6. `TcpIpReset`
7. `RestartNetworkAdapters`
8. `RestartSpooler`
9. `ClearPrintQueue`
10. `RestartUpdateServices`
11. `GpUpdate`
12. `TimeResync`
13. `Dism`
14. `Sfc`

The set is fixed in code. There is no generic command, executable, service-name or adapter-name interface.

## One-UAC phased execution

Administrative actions use one authenticated worker lifetime with explicit phases and session/nonce-bound IPC. Parent-side actions remain in the original interactive-user context; machine-level actions run only after successful worker launch/UAC and protocol validation. Network-disruptive work is deliberately late.

The worker does not impersonate the interactive user. Alternate-admin elevation is supported without treating the administrative account as the target user profile. `CleanTemp` remains guarded by verified original-user/session/profile rules and is not silently moved into an arbitrary elevated context.

## Safety boundaries

0.16.0 does **not** provide or permit:

- disabling, stopping, excluding, uninstalling or weakening Defender, AV, EDR/XDR, firewall or other protective software;
- arbitrary PowerShell/CMD/script or arbitrary executable execution;
- arbitrary service or network-adapter targets;
- Event Log clearing;
- credential or user-profile deletion;
- forced reboot or forced logoff;
- raw/full SMART, broad system-handle enumeration, treemap or stress/stability workload.

Missing telemetry remains unknown/partial rather than healthy by implication. Human-readable localized framing is separate from raw provider evidence.

## Red-batch pilot restriction

**Do everything / Сделать всё must first be tested only on an approved disposable/test workstation.** It can intentionally disrupt the endpoint and active remote session. In particular it may:

- sever or interrupt VPN, RDP or ordinary network connectivity;
- release/renew DHCP and reset Winsock/TCP-IP state;
- restart network adapters;
- restart print/update-related services;
- delete pending print jobs;
- refresh machine/user Group Policy;
- resynchronize time;
- run DISM and SFC;
- leave Windows reporting that a reboot is required.

Do not use the red batch as the first live validation on a production workstation. Keep a local recovery path and record before/after evidence.

## Validation boundary

Hosted CI validates warnings-as-errors build, source and published-EXE self-tests, bilingual/localization contracts, exact action coverage, phased protocol/runtime tests, portable/security negative tests, FileVersion/checksum and pilot-bundle construction. Real disruptive repairs are not executed by hosted CI.

Managed Windows 11 pilot acceptance remains mandatory for interactive UAC, alternate-admin credentials, RDP/DPI, VPN/EDR coexistence, representative OEM/storage providers and the real red-batch disruption/recovery sequence. Use [`docs/E2E-TEST-PLAN.md`](../E2E-TEST-PLAN.md).
